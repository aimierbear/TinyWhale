# Terminal-Bench 2.1 method evaluation

This directory is the reproduction entry for the one-time Terminal-Bench 2.1 method evaluation named by the implemented Agent Note. It is **provided, not run**: the local environment has no `DEEPSEEK_API_KEY` and the repository does not vendor the upstream trajectory data, so no result is claimed here.

## Input

1. Clone upstream at commit `115de305f23ed89bc42e86e010853c40059f3f7d`.
2. Sample task directories from `data/terminal_bench_2.1_trajs/mini-swe-agent_deepseek-v4-flash` in lexicographic order.
   Take the first 20 task directories that contain five `*_trajectory.json` files.
   Use all five trajectories per task.
3. For each task, export one JSONL record using the upstream `loaders.py` extraction rules:

```json
{"task": "<task name>", "problem": "<problem text>", "candidates": [{"id": "<trial_name>", "text": "<formatted trace>", "reward": 0}], "rewards": [0, 1, 0, 1, 1]}
```

`reward` is the upstream held-out `reward` field per trajectory; `problem` and `text` come from `_tb_extract_problem` and `_tb_format_trace`.

## Run

Run the TS `select` through the harness on each exported task with the Terminal-Bench criteria and the benchmark entry settings:

- provider/model: the conversation route in force (DeepSeek official route)
- `criteria`: bundled `terminal_bench`
- `nEvaluations`: 2
- `pivots`: 2
- `seed`: 0

Invoke one task at a time through the ordinary `verify` tool, or through a script that calls `ctx.verifier.select` with the same request fields. No repository script wraps the real-API run; an offline runner may live in `scripts/` once the harness gains a stable CLI evaluation entry.

## Record

Write one JSONL record per task:

```json
{"task": "<task name>", "selectedId": "<candidate id>", "selectedReward": 1, "maxReward": 1, "ranking": [{"candidateId": "...", "score": 0.81}], "calls": 36, "usage": {"inputTokens": 1, "outputTokens": 1}}
```

Report these aggregate fields beside the data path and model route:

- sampled task count
- tasks where `selectedReward == 1` divided by sampled task count (verifier-selection pass rate)
- upstream Pass@1 on the same subset (any `rewards` entry equals 1)
- total nested calls and token usage

## Consistency claim

Do not claim Terminal-Bench 2.1 parity until the recorded verifier-selection pass rate is at or above the upstream Pass@1 on the same subset, at the sampled MC settings (`nEvaluations: 2`) that replace the upstream logprob expectation. Commit the JSONL and the aggregate record together with the data path and model route used.
